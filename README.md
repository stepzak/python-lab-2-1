# Лабораторная работа Python(2 семестр)

* **Цель:** Научиться реализовывать пользовательские коллекции и ленивую обработку
задач.

* **Чему я научился:**
    - описание контрактов с помощью **typing.Protocol**
    - работа с дескрипторами
    - работа с property
    - ленивая фильтрация с помощью генераторных выражений

    - создание итераторов с помощью реализации ``__iter__``


## Особенности реализации

### Источник задач(контракт)
* Метод ``load_tasks`` -  загрузка задач в класс(аналог фабричного метода ``create``)
* Метод ``get_tasks`` - получения итератора по загруженным задачам
* [Реализация](src/task_receiver/source.py)

### Задача
* Атрибуты: 
  * ``priority`` - приоритет(от 1 до 10)
  * ``status`` - статус(имеет логические ограничения на переходы)
  * ``description`` - описание(не может быть изменено во время выполнения задачи)
  * ``deadline`` - дедлайн выполнения задачи(опционально)
  * ``payload`` - аргументы задачи(словарь, опционально)

* Свойства:
  * ``expired`` - прошел ли дедлайн выполнения задачи(``bool``)
  * ``time_left`` - сколько времени(в секундах) осталось для выполнения задачи
  * ``result`` - результат выполнения задачи(поднимет исключение, если задача завершилась с ошибкой)
  * ``exception`` - исключение, с которым задача провалилась
  * ``finished`` - завершилась ли задача

* Методы:
    * ``start`` - запустить задачу
    * ``cancel`` - отменить задачу
    * ``to_dict`` - сериализовать задачу

* [Реализация](src/task_receiver/task.py)

### Очередь задач

   * Структура данных: ``heapq``(для обеспечения доступа к приоритетной задачи за ``O(log n)``)
   * Перегрузка оператора сравнения: для корректной работы ``heapq``, структура ``Task`` поддерживает сравнение ``__lt__``(<), при этом само сравнение пришлось "перевернуть"(т.к. ``heapq`` - min heap)
   * Для поддержки возможности итерации был реализован метод ``__iter__``
   * Для поддержки фильтрации был добавлен метод ``filter``, позволяющий фильтровать по любым атрибутам задачи
   * [Реализация](src/task_receiver/task_queue.py)

## Струкутра проекта: 

* **src/sources** - примеры источников ззадач
* **src/task_receiver/source.py** - контракт взаимодействия
* **src/task_receiver/descriptors.py** - дескрипторы
* **src/task_receiver/exceptions.py** - исключения
* **src/task_receiver/task.py** - класс задачи
* **src/task_receiver/task_queue.py** - класс очереди задач
* **src/utils** - утилиты(в данном случае декоратор *@strict_annotations*, поднимающий исключение в runtime в случае несовпадения типов аргументов)
* **src/consumer.py** - функция, принимающая на вход источник задач
